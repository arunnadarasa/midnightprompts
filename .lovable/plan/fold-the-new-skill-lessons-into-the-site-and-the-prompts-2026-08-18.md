# Fold the new skill lessons into the site and the prompts

I compared the two active skills against what this project already carries. Two real gaps exist.

## What's actually new

**Midnight skill (active copy) has a section the project copies don't:** "2026-08 update — ipsmidnight lessons (Undeployed on Fly + UI-driven deploy)" — about 75 lines covering:

- Node RPC has exactly one working shape: publish 9944 as a pure `tls` service and use `wss://<app>.fly.dev:9944`. `.internal` is IPv6-only 6PN, `.flycast` answers nothing without a private IP, and Fly's `http` handler kills the WebSocket mid-proof.
- The indexer fails **silently** — unreachable node means an empty chain and block 0 forever, which looks like "nothing anchored". Probe it as its own step.
- Runner-machine pattern: a 4th Fly machine with a volume for compile/deploy/anchor/verify, driven by the Machines `exec` API, printing `RESULT {json}` lines so the UI can poll and render a terminal.
- SDK v4 provider gotchas: minimum storage-password length, and `httpClientProofProvider` needing the same `NodeZkConfigProvider` instance or the proof server 400s on `/check`.
- Verification honesty: ledger membership is the only proof, persist the salt or the anchor is permanently unverifiable, minimise credential claims, label what you did not check.
- Key/state hygiene and graceful degradation when `FLY_API_TOKEN` is missing.

**Conversely, the project copies carry the m402 section the active copy lacks.** Neither file is a superset, so this is a merge, not an overwrite.

**Identus skill:** the `/identus` page already covers the core (pinned images, application roles, 6PN, DIDComm 8090, grace period, memory, poll cap, connectionless issuance). Not yet reflected anywhere: the browser ZK age-proof binding, reading crash-loop boot logs through the machine `exec` API rather than the log stream, deterministic `DEFAULT_WALLET_SEED`, `(user_id, kind)` unique-index scoping, and the Sprites-sandbox limits.

## What I'll change

1. **Merge the skill files.** Add the ipsmidnight section to `.agents/skills/lovable-midnight/SKILL.md` and `public/skills/lovable-midnight/SKILL.md` (keeping m402), plus its new failure modes and anti-patterns appended to the existing tables. Result: both project copies are a superset of the active one.

2. **Mega-prompts** (`src/lib/mega-prompt-variants.ts`):
   - New `FLY_RUNNER_LESSONS` block appended to the `undeployed-fly` variant only: the `wss://…:9944` rule, silent-indexer probe, runner machine + `RESULT {json}` polling, prepare-step versioning, existence-probing stored Fly state.
   - New `VERIFICATION_HONESTY` block for every network: ledger membership is the only proof, persist salts, minimise claims, render unchecked things as unverifiable, never derive a green badge from your own database.
   - Extend the SDK-provider rules with the storage-password minimum and the shared `NodeZkConfigProvider` instance.
   - Add the "status functions degrade to `unconfigured`" rule to the frontend standards block.

3. **`/identus` page:** three additions — a ZK-proof-binding card (age proof over a credential's `dob`, proven in the browser so the JWT never leaves the page), a "reading a crash-looping agent's logs" note (machine `exec`, not the log stream), and two rows on the failure table (rotating wallet seed; `unique (user_id)` blocking a second stack per user).

4. **`/known-issues`:** add the silent-indexer trap and the Fly `http`-handler WebSocket kill, both of which read as Midnight bugs but aren't.

5. **Regenerate the download bundles** — the 16 per-network/OS files plus the streamed multi-GB `llms-full.txt`, re-externalised as assets, with `public/llms-full.meta.json` refreshed. This is the slow part; everything above works without it, and it can be deferred if you'd rather ship the text changes first.

## Technical notes

- Prompt blocks are composed per network variant in `src/lib/mega-prompt-variants.ts`; the Fly runner block gates on `network === "undeployed-fly"` while the honesty block is unconditional.
- Bundles are regenerated by `scripts/build-llms-full.mjs` (already streaming, so no OOM) and uploaded through `lovable-assets`; only the `*.asset.json` pointers change in the repo.
- No schema or backend changes.
